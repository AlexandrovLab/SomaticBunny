# SomaticBunny regression tests

Small, deterministic tests for the parts of the pipeline that have had bugs before: the consensus
rules, panel-of-normals handling, VAF arithmetic and the structure of the final VCFs. Everything runs in
a minute on a laptop; no sequencing data and no database are needed.

## What is covered

| File | Guards against |
|---|---|
| `test_consensus.py` | wrong scenario membership (1 vs 2 PASS callers), equivalent indel spellings counted twice, duplicate records within one caller counted twice, an empty caller file breaking the run, panel-of-normals veto (`-p`), scenario 6 threshold demotion and rescue, MNV decomposition, multi-allelic splitting, viral / chrM / unplaced contigs entering the consensus, `--callable_bed` and `--consensus_contigs` restriction |
| `test_vcf_structure.py` | scenario and final VCFs that htslib cannot parse, INFO keys used but not declared, unsorted or incomplete final VCFs |
| `test_vaf.py` | wrong SNV or indel counts and VAFs, loci files with duplicates, schema drift of the VAF table |
| `test_static.py` | shell, Python and YAML syntax; `-pon` passed without a panel; outputs anchored to `projectDir`; consensus default region set |
| `test_nextflow.py` | `main.nf` and every module compile (`-preview`); RN7 refused without opt-in and run without `-pon` with it; invalid `--first_step` and bad sample identifiers refused; outputs under the launch directory |

Inputs are generated by `make_fixtures.py` from a seeded random reference (24 tiny primary
chromosomes, `chrM`, `HPV16`, an unplaced contig), five caller VCFs in each caller's own layout and two
BAMs with known REF/ALT read counts. The `CASES` table in that file is the single source of truth for
every expectation.

## Running locally

```bash
conda env create -f tests/environment.yml                  # python 3, bcftools, samtools, pysam, pytest, nextflow
conda env create -f tests/environment-biasfilter.yml       # python 2.7 for the DKFZ bias filter (scenario 6)
conda activate somaticbunny-tests
git clone https://github.com/DKFZ-ODCF/DKFZBiasFilter tests/_deps/DKFZBiasFilter   # or SB_DB=/path/to/database
SB_BIASFILTER_PYTHON=$(conda run -n somaticbunny-biasfilter which python) pytest -v tests
```

The pinned bias-filter commit is Python 2 code, hence the second environment; `conftest.py` probes it
once and skips the scenario 6 tests with the reason if it cannot run (CI treats that skip as a failure).
Without `nextflow` on the PATH the preview tests are skipped. On TSCC, `SB_DB=$DB` makes the tests use
the database's own copy of the bias filter.

## Continuous integration

`.github/workflows/ci.yml` runs the lint job and the full test job on every pull request and on pushes
to `main`. A pull request that breaks a consensus rule, declares an INFO key wrongly, changes a VAF
count or makes `main.nf` fail to compile turns red.
